Control de Inventario — Mercado Libre

Gestión operativa y financiera del inventario para vendedores de Mercado Libre, sobre PostgreSQL local (Docker) o en la nube (Neon).

Problema
Un vendedor necesita saber qué tiene, qué se estanca y cuánto capital está inmovilizado, con un historial confiable y sin frenar la operación diaria para calcularlo.
Arquitectura
UI en PySide6 que solo habla con una capa de servicios. El stock únicamente cambia mediante movimientos inmutables (entradas, ventas, devoluciones y ajustes), lo que deja una auditoría completa por producto.
Logros
Analítica batch aislada en una transacción REPEATABLE READ READ ONLY: lotes paginados por llave, agregación en PostgreSQL con índices dedicados y una sola conexión con límite de tiempo por consulta.
  • 4ejes de analítica: salud de stock, rotación, valuación y anomalías de catálogo
  • 0escrituras posibles durante la analítica (transacción de solo lectura)
  • 3checks de CI en cada push: Ruff, Pytest y gitleaks
  • Python 3.11+
  • PySide6
  • PostgreSQL
  • Docker
  • Neon
  • Pytest
  • Ruff

Asymmetric Snake AI

Snake asimétrico en tiempo real donde un agente ofensivo gana por control territorial y estrangulamiento táctico, no por comer más.

Problema
Las IAs clásicas de Snake solo persiguen comida. El reto: un agente que ataque —cortar rutas, sellar cuellos de botella— y que haga visible su razonamiento en cada tick.
Arquitectura
Núcleo puro e inmutable sin pygame, motor determinista por semilla y agentes intercambiables (Strategy). El agente combina BFS temporal, diagramas de Voronoi, A* ponderado y puntos de articulación (Tarjan) para elegir su modo táctico por utilidad.
Logros
Vence a un baseline greedy no trivial terminando más corto en promedio: gana por posición, no por tamaño. Overlays de depuración muestran en vivo la partición espacial, las rutas A*, los vectores de intercepción y los cuellos de botella.
  • 65 %de victorias contra un agente greedy (20 semillas)
  • 3.2 msde latencia media por decisión: menos del 5 % del presupuesto a 15 ticks/s
  • 117pruebas en verde con tipado mypy --strict
  • Python 3.12
  • pygame-ce
  • A*
  • Voronoi
  • Tarjan
  • pytest
  • mypy

Web app · Frontend experimental

The Darwinian Calculator

Calculadora cuya interfaz evoluciona según los patrones de uso de cada persona mediante computación evolutiva.

Problema
Las interfaces son estáticas aunque cada persona las usa distinto. ¿Puede una UI reorganizarse sola a partir del uso real, sin backend ni librerías?
Arquitectura
Algoritmo genético en el cliente: cada botón es un cromosoma con genes de posición, escala y prominencia. Módulos ES separados para motor evolutivo, UI, almacenamiento y orquestación.
Logros
La interfaz se adapta a la frecuencia de clics y al tiempo de reacción de cada usuario, y conserva su evolución entre sesiones: el ADN de la UI persiste en localStorage. Respeta prefers-reduced-motion.
  • 0dependencias: JavaScript vanilla
  • 70/30peso de aptitud: frecuencia de clics / tiempo de reacción
  • 5interacciones por ciclo de mutación, con resolución de colisiones
  • JavaScript (ES Modules)
  • HTML5
  • Canvas API
  • CSS Glassmorphism
  • Vercel
